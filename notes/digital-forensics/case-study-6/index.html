01

Executive Summary

This document explains the suspected ransomware infection identified on the live workstation. Currently, the IT department’s plan is to immediately disconnect the workstation and reinstall Windows. However, this is highly destructive. This plan outlines how investigators should preserve volatile data, examine the suspected ransomware, and develop a timeline of the attack. The goal is to determine how ransomware entered the system, when encryption began, and whether the workstation communicated with other potentially compromised systems.

02

Forensic Collection Plan (Order of Volatility)

Before collecting any volatile data, it must be ensured that the device is not powered off. If the device is powered off, the system can instantly destroy volatile data such as RAM, running processes, or any active network connections. Shutting down can cause encryption keys in memory to vanish, making it hard to reconstruct the timeline. The following should be collected in order from most volatile to least volatile:

  1. CPU registersHighest volatility; lost immediately on power loss.
  2. Network connectionsActive sessions that may reveal remote endpoints.
  3. Running processesRecord soon after network state; malware may stop or delete itself.
  4. RAMMay hold keys, fileless malware, and attacker commands.
  5. Temporary file systemsShort-lived artifacts that can disappear during reboot or cleanup.
  6. Disk imageLeast volatile; collect after logs and memory when possible so attackers cannot first erase evidence.

These logs should be collected prior to the disk image since attackers can potentially delete them. (ScienceDirect, 2013) Capturing network connections and memory first matters because malware may attempt to self-destruct or embed itself deeper into the OS. This sequence is noted in RFC 3227 as the normal standard. (Clocked Out, 2026; Jha, 2026)

03

Technical Analysis of Volatile Artifacts

Connections are among the most volatile information. They can reveal IP addresses of command-and-control (C2) servers—the infrastructure ransomware may communicate with—and can support further investigation into where the attack activity is directed.

Running processes show which program is doing file encryption, its location, and how it started. For example, if Microsoft Word launches PowerShell and PowerShell then starts a suspicious executable, that could indicate that a malicious document or script initiated the activity. However, this behavior alone does not prove that a phishing email was the initial attack vector. Additional evidence is needed to confirm how the process started.

Memory analysis is crucial during an active attack because RAM may contain information about the ransomware: running programs, hidden malware, passwords, network connections, and commands the attacker typed. If the malware is fileless, it may exist only in memory in order to avoid IPS/IDS and antivirus. The RAM might also contain encryption or decryption keys. (Nelson, Phillips, & Steuart, 2019)

04

How Logs Show How the Attacker Got In

Windows event logs can show failed and successful logins, including remote access via RDP. They show what programs were started and whether logs were cleared. Email and firewall logs can be traced if a malicious attachment or download started the attack. EDR alerts show exactly when security software flagged a potential issue. Ultimately, logs provide a time frame for when each event occurred, helping identify when an attack may have begun.

05

Ransomware Event Timeline

The following timeline represents the suspected sequence of events. Exact times must be established through examination of the evidence rather than assumed.

Suspected ransomware sequence and evidence to examine
Order Event Evidence to examine
1 Initial access Firewall, event logs, email records, browser history, and remote access records
2 Ransomware executed Suspicious processes running as seen in Task Manager and process listings
3 C2 server communication Active network connections seen by netstat and captured volatility data
4 Files encrypted Changed file extensions and files that cannot be opened
5 Ransom note displayed Ransom-note file metadata, screen documentation, and user observation

06

Investigation Challenge: Correlation vs. Causation

In this investigation, correlation and causation are not the same thing. Correlation means that two things are connected to each other. For example, file encryption and a C2-looking connection may be correlated. Causation is when one action leads to the result of the other—for example, claiming that an IP address found in active connections is the C2 connection and caused the ransom.

Just finding an active connection and IP is not proof that this was the cause of the encrypted files. The IP could be associated with a legitimate service such as a Windows update. Further evidence may need to be correlated, such as third-party intelligence that relates the IP to the ransomware family (for example, public reporting from vendors such as Kaspersky).

A suspicious connection does not prove that the IP caused the attack. To support that claim, investigators would need to show that the program making connections is the same program encrypting the files, with matching timestamps, and that the IP is flagged as malicious. Until that evidence is available, the external connection should be described as suspicious rather than confirmed as the cause of the attack.

07

Conclusion

The workstation should not be shut down or reinstalled until the necessary forensic evidence has been collected and preserved. Investigators should prioritize volatile information, capture memory, preserve relevant logs, and create a forensic disk image. Hashes and chain-of-custody records should be maintained to support the integrity of the evidence. By comparing process information, network activity, logs, and file-system artifacts, investigators can develop a more reliable timeline and determine how the ransomware operated. The final findings should distinguish confirmed evidence from assumptions so that the investigation does not claim more than the available evidence supports.
