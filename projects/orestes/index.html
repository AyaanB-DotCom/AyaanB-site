01 / Introduction

Turning radio observation into a handheld experience

Orestes began with a simple idea: compact wireless tools do not have to feel like dense diagnostic menus.

I wanted a device that could make nearby radio activity legible at a glance and still feel playful enough to carry. The Nintendo DS became the visual cue: bold icons, direct touch interaction, encounter cards, and a lightweight progression system wrapped around practical Wi-Fi and Bluetooth observations.

The result is a self-contained toolkit. It does not need a companion phone, cloud account, or remote service. Scanning, display, encounter history, points, and badges all live on the ESP32-S3.

02 / Hardware

A complete interface on two inches of glass

The project runs on a Waveshare ESP32-S3-Touch-LCD-2. Its dual-core ESP32-S3 provides Wi-Fi and BLE, while 8 MB of PSRAM supports the interface and scan data. A 240 × 320 ST7789 display and CST816S touch controller turn the board into a complete handheld instead of a sensor that must report elsewhere.

That compact target shaped the software. Lists have to be readable, detail views have to prioritize the fields that matter, touch targets cannot be fragile, and scan state must remain understandable without a keyboard or terminal attached.

The full repository documents the required Arduino libraries, board profile, partition scheme, touch-driver setup, GPIO assignments, and flashing sequence.

03 / Interaction model

Four modules, one exploration loop

  1. Wi-Fi scanner

    Nearby access points become a touchable list of SSID, BSSID, signal strength, channel, encryption, and estimated distance. Selecting a row opens a focused detail view.

  2. BLE scanner

    Bluetooth Low Energy advertisements are organized by name, address, signal, device type, and connectable status. Other Orestes devices receive a recognizable marker.

  3. Scan map

    Observed signals are placed on an on-device grid so repeated scans can show density and relative movement. It is a local visualization, not a GPS-backed geographic map.

  4. StreetPass

    Two nearby Orestes devices can recognize one another, ask both users to confirm, and save an encounter card. Proximity influences points, while saved encounters unlock badges over time.

04 / Engineering choices

Building around the constraints

The interesting work was not adding one more scanner. It was making several radio behaviors coexist inside a small embedded interface.

  1. On-device firstScan results, encounter cards, nicknames, points, and badges stay local instead of depending on a phone or web service.
  2. Touch over terminalRescanning, opening details, navigating lists, and confirming encounters are all direct touchscreen actions.
  3. Visible radio stateThe BLE scanner briefly pauses Orestes advertising while it scans, making contention between discovery and discoverability an explicit application behavior.
  4. Deliberate flash budgetThe interface and radio features require a larger application partition, so the build targets the board’s Huge APP layout rather than the default flash allocation.

Those constraints—and the fixes for touch-driver placement, ESP32 core compatibility, upload mode, serial permissions, and BLE API differences—are documented in the repository rather than duplicated here.

05 / Responsible operation

Observation for recon; consent for encounters

The Wi-Fi module reads broadcast network metadata. It does not join networks, capture authentication handshakes, inject frames, deauthenticate clients, or attempt credential recovery. BLE discovery similarly organizes advertisements already visible to nearby receivers.

StreetPass is the intentional active exception: Orestes advertises its shared service and can connect to another Orestes unit, but an encounter is registered only after both users tap Connect. That separates observational reconnaissance from the project’s explicit, consensual peer-to-peer feature.

The toolkit is designed for education, personal experimentation, and lawful RF observation. Its value is in making nearby protocol metadata understandable—not in gaining access to another system.
