Heaven's Night

Investigating a suspected malware infection: from Minecraft to Ren'Py. A Malwarebytes report, a reused launcher hash, and a packaged visual-novel archive that still leaves the infection chain incomplete.

Case study · November 2026 · Ongoing investigation

Focus
Digital forensics, malware analysis, threat intelligence
Trigger
Malwarebytes report, Windows 11 host, Nov 4, 2026
Pivot
Ren'Py launcher (Setup.exe) and packaged archive
Status
Ongoing — no malware family conclusively established

Investigation status

This case remains open. Confirmed observations and unfinished leads are kept separate on purpose.

The findings documented here reflect evidence collected and analyzed so far. Certain behaviors and relationships remain unverified, and conclusions may change as additional artifacts are examined. No malware family, confirmed infostealer activity, or complete infection chain has been conclusively established.

01 / Introduction

How it started

The case began when I was contacted by a friend regarding an individual whose computer had reportedly been infected with malware. I was provided with a Malwarebytes scan report and several potentially suspicious files for investigation.

The affected computer was running Windows 11, and a Malwarebytes scan performed on November 4, 2026, identified four suspicious files. All four were reported as quarantined.

The initial suspicion was that the infection originated from a malicious Minecraft .jar mod. That seemed plausible at first, especially because two of the detections involved a Minecraft launcher and its shortcut. There was insufficient evidence to establish that connection.

During further investigation, preliminary open-source intelligence and antivirus analysis shifted attention toward another suspicious file: Setup.exe. The executable sat inside a directory named RT809H_Software_Free_Download_Archive_win_7552.

What initially appeared to be a straightforward investigation into a potentially malicious Minecraft mod had turned into something more complicated.

02 / Unexpected discovery

An unexpected discovery: Ren'Py

I began researching Setup.exe using VirusTotal, a platform that aggregates antivirus detection results, file metadata, and behavioral analysis.

One of the first interesting discoveries was that the executable appeared consistent with a legitimate launcher for the Ren'Py Visual Novel Engine. Ren'Py is a framework commonly used to develop visual novels and other interactive applications, particularly story-based games involving dialogue, images, and player choices.

At the time of investigation, the executable had a VirusTotal detection ratio of just 1 out of 71 antivirus vendors, with Malwarebytes being the only vendor flagging the file. That raised a useful question: how could an executable associated with so many suspicious files have such a low detection ratio?

A legitimate application launcher does not necessarily contain the code responsible for everything an application does. Its primary purpose may simply be to initialize the framework and load the additional libraries, scripts, and resources needed for the application to function. An executable itself may not contain malicious code, even if it is distributed alongside malicious files.

Could a legitimate application launcher be used to execute malicious code stored elsewhere in a software package? That question became the focus of the investigation.

03 / File relationships

Following the VirusTotal evidence

As examination continued, the same executable appeared under numerous different filenames.

Some were variations of Setup.exe, while others were associated with various games and software packages. Because the SHA-256 hash was identical, those different filenames all referred to the same executable content. The launcher appeared to have been reused across many different applications.

VirusTotal displayed more than 20,000 relationships categorized as execution parents. While examining those results, numerous related files and compressed software packages showed substantially higher antivirus detection ratios than the executable itself. Some of those packages appeared to be associated with pirated software and repackaged games.

One possibility is that malicious software distributors are reusing legitimate Ren'Py executables as part of modified or repackaged applications. In that scenario, the launcher itself might be legitimate, while other files included with the application contain the malicious functionality.

Evidence boundary

Low detection does not prove safety. Association with suspicious files does not prove this executable is malicious.

These relationships provided investigative leads, but they were not enough to establish what actually happened on the affected computer. The surrounding application files had to be examined next.

04 / Static examination

Examining the software archive

Following the initial VirusTotal investigation, a ZIP archive associated with the suspicious software package became available. It was examined using Kali Linux inside an isolated virtual machine, beginning with static analysis rather than executing the application.

The archive contained 1,529 entries, with approximately 784 MB of uncompressed data. Inside were recognizable Ren'Py application directories, Python libraries, compiled resources, graphical assets, and several unusually named files. That strongly suggested a packaged Ren'Py application rather than a standalone Windows installer.

One of the most important findings was something that was not there.

Where was Setup.exe?

The original Malwarebytes report identified SETUP.EXE inside an extracted directory with the same name as the archive. Yet the ZIP examined did not contain a standalone SETUP.EXE. Instead, it contained setup.py, a Python script belonging to the Ren'Py framework. Those are two different files.

Inspection of the beginning of setup.py found standard framework functionality for locating application directories, resources, and save files. No obviously malicious instructions were identified in the portion examined.

The absence of SETUP.EXE introduced an important limitation. It is possible that the executable had been quarantined before the archive was obtained, that a different version of the archive was provided, or that the files had been repackaged. None of those explanations has been confirmed. That meant the archive could not be established as an unchanged copy of the original software package. Nevertheless, it contained several files worth investigating.

05 / Application structure

Looking inside the application

During the archive examination, several files with unusual extensions and sizes stood out. Some were hundreds of megabytes, while others were only a few hundred bytes. These included a Ren'Py resource archive, unusually named binary data, and a small hidden file containing what appeared to be encoded text.

Hexadecimal headers were examined to determine whether they used recognizable file formats. One file, libwin.rpa, began with an RPA-3.0 signature, identifying it as a Ren'Py archive. Other files did not contain immediately recognizable signatures in the portions examined.

That does not necessarily indicate malicious activity. Applications frequently use custom resource formats, compression, and encoded data for legitimate purposes. These files may still help explain what the application does during initialization. The objective now is to determine what they contain and whether they are referenced by the application's startup code.

The investigation is gradually moving beyond antivirus detections and into examining the application's actual structure.

06 / Runtime artifact

An interesting finding in the execution log

One of the more interesting discoveries was a log.txt file included inside the archive. The log recorded a Ren'Py application initializing in a Windows environment on November 2, 2026. It showed the application loading its scripts, initializing various components, and eventually preparing its graphical interface.

During initialization, the log contained an HTTP response showing status code 503, followed by a reference to a compiled Ren'Py script named script.rpyc. An HTTP 503 response generally indicates that a server was unavailable or unable to fulfill a request.

That raised the possibility that the application attempted to communicate with an external service during startup. Was it checking for an update, requesting application data, or attempting something else? At this stage, those questions remain unanswered. The log did not reveal the destination, request contents, or purpose of the operation. It also has not been conclusively linked to the affected person's computer.

What makes the finding useful is that it provides a specific location in the application's initialization process to investigate further. The compiled script referenced in the log was not visible as a standalone file in the outer ZIP archive. It may be stored inside another packaged resource, although that has not yet been confirmed. Recovering and examining this script is now one of the main priorities.

07 / Related detections

What about the other Malwarebytes detections?

While the investigation has primarily focused on the Ren'Py application, the original Malwarebytes report identified three other files. These included a Minecraft launcher, its taskbar shortcut, and a DLL named ETWPROVIDERS.DLL found inside a temporary Windows directory.

The DLL is particularly interesting because temporary directories are sometimes used by malicious software to extract or stage additional components. There are documented malware campaigns that abuse Ren'Py applications to load additional payloads. Some involve multiple execution stages and temporary file extraction.

The existence of similar techniques does not establish that this sample belongs to one of those campaigns. At present, it has not been confirmed that the Ren'Py application created, loaded, or otherwise interacted with the DLL identified by Malwarebytes. The Minecraft-related detections may also be unrelated.

One goal of this investigation is to determine whether these files form part of the same infection chain or represent separate detections on the affected computer. The evidence should not be forced into a particular explanation without support.

08 / Current findings

What has actually been established?

At this stage, several observations have been established.

  1. Four quarantined detections

    The original Malwarebytes report identified four suspicious files and reported that all four were quarantined.

  2. A reused Ren'Py launcher hash

    One of those files, Setup.exe, has a hash matching a widely encountered Ren'Py launcher with a relatively low VirusTotal detection ratio.

  3. A packaged Ren'Py archive

    The available ZIP contained compiled resources, Python libraries, and several unidentified files consistent with a packaged Ren'Py application.

  4. An HTTP 503 during initialization

    An application log inside the archive documented a previous initialization event involving an HTTP 503 response and a compiled Ren'Py script.

Several important questions remain unanswered. The original SETUP.EXE was not present in the archive examined. The compiled startup script has not yet been recovered, and the unidentified application resources have not been fully analyzed.

More importantly, no malicious command-and-control destination, confirmed data theft, or complete infection chain has been established. The available evidence is sufficient to justify further investigation, but not enough to conclude that the supplied archive independently contains or executes an infostealer.

09 / Next steps

Where the investigation goes next

The next step is to continue examining the internal Ren'Py archive and attempt to recover the compiled startup script referenced in the execution log. From there, the work is to understand what the application actually does during initialization, determine the purpose of the unidentified resources, and investigate whether any of its behavior can be connected to the other Malwarebytes detections.

If the available evidence allows it, controlled dynamic analysis is also planned to observe file creation, process activity, and network communication. The ultimate goal is to reconstruct an infection chain supported by verifiable evidence rather than assumptions.

Even if some of the suspicious files turn out to be legitimate or unrelated, documenting those findings is an important part of the forensic process.

Working conclusion

Heaven's Night remains an active investigation.

What started as a suspected malicious Minecraft mod has developed into a broader investigation involving a Ren'Py application, suspicious file relationships, and unidentified application resources. A file can appear relatively harmless in isolation while being distributed as part of a potentially malicious application. At the same time, an association with suspicious files does not automatically establish malicious behavior. This case continues to reinforce the importance of examining available evidence, questioning initial assumptions, and separating confirmed observations from hypotheses.
